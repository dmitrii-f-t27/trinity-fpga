# GF+A v3 — вектор 2: downstream-aware метрика выбора кармана (луп 22.07.2026)

`[измерено — SW proxy, CPU]` (микро-LM) + pod-скрипт для `[измерено — GPU]` (29M, за пользователем).
seed=20260722. Харнессы `testE_v3.py`, `testE_v3_holdout.py`; pod `../../webterm_gfplus_v2select.py`.

## Проблема, которую закрывает вектор 2

v1/v2 (инв. №15/№17) выбирают карман по **чистому MSE весов** `Σ(w−q(w))²`.
Но downstream-ошибку слоя даёт ошибка **выхода**: `‖Wx − q(W)x‖²`. При калибровочных
активациях X вклад ошибки веса `W_ij` взвешен диагональю Гессиана слоя
`H_jj = E[x_j²]` (метод важности столбца из OBQ/GPTQ). Downstream-aware выбор:

```
carman* = argmin_p  Σ_j H_jj · (W_ij − q_p(W_ij))²      # взвешенный MSE
```

## Три под-направления (реализованы)

- **2а — sensitivity-выбор** (`gfplus_adaptive_v3.py: gfplus_a_v3(metric='hess')`):
  диагональ Гессиана `hutchinson_diag_from_acts(X) = E[x_j²]` вместо равновесной метрики.
- **2б — честная сверка**: обе метрики (MSE / Hessian) оцениваются **одной** downstream-метрикой —
  SQNR **выхода** слоя `Y=X·Wᵀ`, а не MSE весов (иначе сравнение нечестно, урок бага v1→v2).
- **2в — holdout-абляция** (`testE_v3_holdout.py`): выбор кармана считаем на **calib**-активациях,
  оцениваем на **независимых val**-активациях. Иначе Hessian-выбор переобучается под калибр-набор.

## Результат (микро-LM, 2 слоя W1 192→256, W2 256→65)

### 2б — in-sample (выбор и оценка на одних активациях)
Hessian-выбор меняет решение для десятков строк, но downstream-ΔSQNR **непостоянен по знаку**:
яркие плюсы (W2 N6 K8 **+1.130 дБ**, W2 N4 K1 +0.534) соседствуют с минусами (W2 N8 K1 −0.516).

### 2в — holdout (честный, выбор на calib / оценка на val) — ГЛАВНЫЙ ВЫВОД
| | значение |
|---|---|
| среднее ΔSQNR_val (Hessian − MSE) по 12 ячейкам | **+0.055 дБ** |
| медиана | **+0.010 дБ** |
| знак-баланс | **7 лучше / 3 хуже / 2 равно** |
| максимум | W2 N6 K8 **+1.123 дБ** |
| минимум | W2 N8 K1 **−0.867 дБ** |

**Честный вердикт `[измерено — SW proxy, CPU]`:** downstream-aware (Hessian) выбор кармана
**в среднем слегка помогает, но непостоянно и в пределах шума** — на однородных весах микро-LM
**НЕ окупается железно**. MSE весов оказывается неплохим суррогатом downstream на этой модели.
Есть отдельные слои (W2 6-бит) с реальным выигрышем >1 дБ — сигнал, что на слоях с сильно
неравномерной важностью входов (attention-проекции больших моделей) выигрыш может быть больше.

## GPU-подтверждение на 29M — гипотеза ПОДТВЕРЖДЕНА `[измерено — GPU, seed=42]`

`webterm_gfplus_v2select.py` (RTX PRO 4500 Blackwell, torch 2.11.0+cu128, 9L d=512,
3000 шагов FineWeb, 27 Linear) снял реальные активации через forward-hooks,
сравнил MSE-выбор vs Hessian-выбор по downstream-SQNR на holdout. Полная сводка —
`v2select_gpu_29M_seed42.md`.

| bits | среднее ΔSQNR | медиана | лучше/хуже/равно |
|---|---|---|---|
| 4  | **+0.878 дБ** | +0.080 | 16/1/1 |
| 6  | **+0.697 дБ** | +0.234 | 18/0/0 |
| 8  | **+0.680 дБ** | +0.170 | 18/0/0 |

**Ключевое:** выигрыш ЛОКАЛИЗОВАН в глубоких `linear1` (FFN up-proj) и РАСТЁТ с глубиной:
`l.0.linear1` +0.008 дБ → `l.8.linear1` **+3.102 (4б) / +2.155 (6б) / +1.825 (8б)**.
`linear2` (down-proj после активации) выигрывает мало (+0.01…+0.36). Механизм = неоднородность
важности столбцов на глубоких FFN — то, чего НЕ было в однородном микро-LM.

**Вывод инвертирует микро-LM:** downstream-aware (Hessian) выбор кармана GF+A ≥ MSE-выбора
по SQNR выхода на 52 из 54 ячеек; маржа растёт с глубиной/гетерогенностью.

Запуск (env ПЕРЕД python; первый прогон ~5 мин ставит torch cu128 и один раз re-exec-ается):

## Границы (BINDING)

- 1 микро-LM (2 слоя), 2 GPU-слоя ещё не прогнаны;
- метрика downstream = SQNR выхода слоя (линейный суррогат), НЕ полная model-BPB;
- H_jj = ДИАГОНАЛЬНОЕ приближение Гессиана (как OBQ/GPTQ), не полный второй порядок;
- выигрыш +0.055 дБ в среднем < визуального порога значимости — заявлять «downstream-выбор
  улучшает GF+A» НЕЛЬЗЯ без GPU-подтверждения; честно: «в среднем нейтрален на микро-LM,
  с редкими выигрышами >1 дБ на отдельных слоях».
