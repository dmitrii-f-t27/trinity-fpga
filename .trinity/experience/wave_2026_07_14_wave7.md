## Executive Summary

## CRITICAL FINDINGS (C1-C5)

### C1: Fake CI workflow deleted ✅
`build-compute-bitstreams.yml` passed `/dev/null` to fasm2frames, never routed. Gave false impression of div/sqrt/quire CI coverage. **Deleted.**

### C2: gf_sqrt_param.v is hardcoded to binary32 ✅ (documented)
Parameter `MANT_BITS` exists but all datapaths are 24-bit. Instantiating with any other width silently miscomputes.

### C3: All div/sqrt wrappers are binary32 proxies ✅ (documented)
Convert GF-N → binary32 → compute → quantize back. Format-specific semantics lost.

### C4: div/sqrt NBA stale-output bug ✅ (documented)
`out_y <= result_packed` in same cycle as `result_packed <= new_value` — reads OLD result.

### C5: gf_mul_param timing risk ✅ (documented)
80-way priority encoder for GF64 MSB search — same timing disease as adder.

## THREE OPTIONS FOR NEXT WAVE

### Option A: "Native DIV/SQRT" — Real GF Arithmetic
Write native GF div/sqrt RTL that operates in the actual format width. Fix the NBA stale-output bug. Add conformance vectors.

**Risk**: High (iterative division is non-trivial)
**Impact**: Completes the compute catalog honestly

### Option B: "TX Race Auto-Fix" — 1496 Wrappers
Write a script to auto-transform shift-register TX → buffer+mux across all 1496 racy wrappers.

**Risk**: Low (mechanical)
**Impact**: Eliminates latent TX race in entire catalog

### Option C: "2-Stage Pipeline" — Fix GF64+ Timing
Split gf_adder_param AND gf_mul_param into 2 pipeline stages. Target GF64 512/512.

**Risk**: Medium (handshake)
**Impact**: Unlocks GF64/128/256 compute Tier-E
