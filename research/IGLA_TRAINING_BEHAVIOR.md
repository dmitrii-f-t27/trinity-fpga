## ОБЪЯСНЕНИЕ: почему BF16 теряет 92.7% обновлений

```
Вес = 0.5 (BF16 представление: 0.5)
Градиент = 0.0003 (типичный gradient в ML)

0.5 + 0.0003 = 0.5003

BF16 имеет 7 бит мантиссы → шаг квантования около 0.5 равен 2^(-8) ≈ 0.0039
0.5003 < 0.5 + 0.0039 → ОКРУГЛЯЕТСЯ ОБРАТНО К 0.5

→ Обновление ПОТЕРЯНО!
→ 92.7% обновлений имеют |Δ| < 0.0039 → все теряются
```

```
GF16 имеет 9 бит мантиссы → шаг около 0.5 равен 2^(-10) ≈ 0.00098
0.0003 < 0.00098 → всё ещё теряется
НО: 63.9% обновлений имеют |Δ| > 0.00098 → они ВЫЖИВАЮТ

→ GF16 сохраняет в 8.7× больше обновлений чем BF16
```

## РАНЖИРОВАНИЕ ФОРМАТОВ ДЛЯ LLM TRAINING

| 1 | **posit16** | **90.8%** | 2.0% err | 0.0017 | НАИЛУЧШИЙ для training |
| 2 | **takum16** | **89.6%** | 2.2% err | 0.0018 | Отличный |

| 6 | BF16 | **7.3%** | **50% err** | 0.0074 | ПЛОХОЙ (нужна loss scaling) |

**Вывод**: Для LLM training без loss scaling:
- 16 бит: posit16 > takum16 > FP16 > **GF16** >> BF16
- 8 бит: невозможно (0% выживаемости)
- GF16 в 8.7× эффективнее BF16 для training без trick'ов
